# STRATA: Descent

A first-person dungeon crawler in three.js. Every image in the game — walls, floors,
enemies, items, icons — is generated by **Z-Image Turbo** through the ComfyUI MCP
server; the maze, the difficulty curve, the loot and the combat are procedural.

Design document: [`GAME_DESIGN_SPEC.md`](GAME_DESIGN_SPEC.md) — the build follows it,
and the spec has been updated wherever implementation proved it wrong.

## Running it

```
npm install
npm run dev          # http://localhost:5177
```

Click **Descend** to play. The art is ~57 MB of 1024² PNGs, so the first load takes a
few seconds; a progress bar shows on the menu.

Source edits hot-reload. New or replaced **images** need a dev-server restart, because
the image list is resolved when the server starts (see *Dev notes*).

## Controls

| Input | Action |
|---|---|
| Mouse | Look (pointer lock) |
| `W A S D` | Move |
| `Shift` | Run |
| Left click / `Space` | Attack |
| `E` / `F` | Interact (stairs, chests) |
| Hold on stairs | `1.5 s` to descend |
| `Esc` | Pause |
| `M` | Mute |

Walk over an item to pick it up. Better gear equips itself, worse gear is sold for
gold. Health comes back only from potions.

## Tests

```
npm test              # levels + loot + movement (headless Node, ~30 s)
npm run test:game     # boots the real game in headless Edge, 21 integration checks
npm run test:keys     # chroma-key QA: measures every generated sprite, non-zero exit if one keys badly
```

All four suites currently pass: 200/200 generated levels solvable, the loot spread
checks, the collision checks, 21/21 integration checks (including that WASD and the
arrow keys move the way the camera actually points), and 57/57 sprites key clean.

Art QA, which renders a report you can look at instead of reading numbers:

```
npm run qa:seams      # seamcheck.png — every tile at 50% offset vs. the engine's mirrored pass
npm run qa:keys       # keycheck.png  — every sprite after the real keying pipeline, with numbers
npm run shot -- index.html play.png 1280 720 "?demo=1&seed=alpha&depth=9&preview=orc&tier=4"
```

Each starts its own Vite server, so they work whether or not `npm run dev` is running.

`test:game` needs a Chromium browser installed; it uses a throwaway profile, so it will
not disturb an open browser window. Individual suites: `test:levels`, `test:loot`,
`test:movement`.

Useful URL parameters:

| URL | What it does |
|---|---|
| `?demo=1&seed=777` | jump straight into a run with a fixed level |
| `?demo=1&depth=7&preview=mage&tier=3` | stand one enemy in front of the camera for art review |
| `?selftest=1` | run the integration checks and print pass/fail |
| `?selftest=1&assets=1` | same, but after decoding every generated image |
| `/seamcheck.html` | texture tiling review sheet (raw vs. the engine's mirrored pass) |

## Adding music

Drop `.mp3`/`.ogg`/`.wav` files into `assets/music/`. Each new depth plays one at
random with a shuffle bag, so no track repeats until the pool is exhausted, with a
1.2 s crossfade. `manifest.json` is optional — it exists only to name or exclude
tracks. With no files the game runs silent.

## Sound effects

There are no SFX files in the repo. All ~30 sounds are synthesised at runtime with
WebAudio, following the recipes in spec §12. If you ever want real files instead,
drop them in `assets/audio/sfx/` named after the recipe (for example
`swing_01.mp3`) and the loader prefers them over the synth.

## Art pipeline

`assets/images/manifest.json` records every image: slug, prompt, seed, size, steps,
filename prefix and the ComfyUI source URL. Prompts are listed in spec §13.5, seeds
are recorded per asset, and a retry records the rejected seed.

Batch 1 (16 textures + 23 enemies, seeds 41000–41038) and batch 2 (8 props + 18 items
+ 8 VFX + 15 UI, seeds 42000–42048) were generated strictly one at a time — the Z-Image
server on the other PC handles a single generation at a time. `items/arrow` took three
attempts; the two rejected seeds are recorded in its manifest entry.

## Dev notes

- **The watcher ignores `assets/` and atomic-save temp files.** Watching those two
  things crashes chokidar on Windows with `EBUSY` and takes the whole dev server down —
  the art pipeline writes PNGs while the server runs, and some editors save by writing a
  `.tmp` file next to the source. They are excluded, so source edits still hot-reload.
  Because the image registry is built from a glob at server start, adding or replacing a
  PNG means restarting the server; a page reload is enough for code changes.
- **Stale-code trap:** if a dev server was started before a fix landed and the fix is not
  reaching the browser, restart the server. `npm run test:game` always starts its own
  server, so a passing test can coexist with a stale tab — that is exactly what happened
  once with the strafe fix.
- **Node is not on PATH** on this machine. Use the full path
  (`C:\Program Files\nodejs\npm.cmd`), and prepend `C:\Program Files\nodejs` to `$env:PATH`
  for scripts that shell out to `node`.
- Levels, spawns, drops and quality rolls all come from one seeded RNG per run, so the
  same seed always produces the same level. Frame-rate-dependent `Math.random()` is
  used only for cosmetics.
